## core

### New features

* **`:SQUASH` entries in `:rev` filters** (#2349)
  Squashes the matched commits out of the filtered history; with `history="no-splice"`
  this enables migrating git-subtree based repositories to josh-sync without duplicating
  history. Bumps the cache version.

* **Filters containing `:SQUASH` are reversible** (#2347)
  Its tree-level inverse is `:/` (nop), making pushes through squashed views possible.

* **`Filter::rev(...)` builder** (#2308)

### Bug fixes

* **Merges with elided parents are no longer pruned to zero parents** (#2348)
  This silently disconnected the history behind a surviving empty-tree parent.

* **Chains with a trailing generative op no longer collapse to `:empty`** (#2326)
  E.g. `:empty:$x="y"` optimized to `:empty` instead of yielding `{x:"y"}`.

* **Chains distribute over composes only when the suffix commutes** (#2327)
  Duplicating a non-commuting suffix (e.g. an `:exclude` with a rename) into every
  branch changed the result.

* **Orphan history stays connected when pushing without a base** (#2314)
  Vendoring a standalone repository no longer collapses its history into a single
  parentless commit (#2205).

### Performance

* **Object reads skip libgit2 hash verification** (#2320)
  Re-hashing every object read was up to 70% of CPU on read-heavy workloads.

* **Read parent ids without loading parent commits** (#2300, #2301)
  Up to -11% on deep-history filtering and less contention on libgit2's object cache
  lock under concurrent proxy load.

## josh-cli

### Bug fixes

* **Non-fast-forward reverse updates are refused without `--force`** (#2350)
  Reverse applies no longer silently discard commits that landed concurrently on the
  input reference.

## josh-compose

* **Compose executors split into separate backend crates** (#2239, #2328)
  `josh-compose-backend` holds the interface, `josh-compose-podman` the Podman
  implementation.
